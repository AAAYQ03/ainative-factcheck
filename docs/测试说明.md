# 测试说明

## 运行方式

```bash
npm test                          # 离线自动化测试（mock 扶摇与 LLM，结果确定，可复现）
npm run smoke -- clean            # 用真实扶摇与 DeepSeek 跑示例稿件
npm run smoke -- wrong-numbers
npm run smoke -- compliance
npm run smoke -- wrong-numbers fuyao_down   # 第二个参数为故障演练：fuyao_down | llm_down | stale
```

线上页面同样提供"故障演练"下拉框，评审可以直接在 URL 上复现下面的失败场景。

## 自动化测试覆盖（`tests/`，共 20 条）

mock 数据录制自扶摇 2026-10-16 ~ 10-22 的真实日K和 2024/2025 年报（`tests/mock.ts`）。

### 主链路
| 用例 | 预期 |
|---|---|
| ② 号稿件：宁德时代 10-21 "大跌8.5%" | ❌ 不符，数据 −12.03%，来源 `/api/a-share/prices/historical`，建议改为 12.03% |
| 营收 4237.02 亿元 / 归母净利润 722 亿元 | ✅ 一致（容差 1%） |

| LLM 返回原文里不存在的引用 | 丢弃，不进入核查 |
| 每条已核实结论 | 必须带 source / field / as_of / unit / method |
| 修订稿 | 只应用"采纳"项；驳回或待处理项保持原文 |

### 数据缺失 / 接口失败
| 用例 | 预期 |
|---|---|
| 扶摇接口不可用 | 全部 ⚠️ 无法核实，整体结论不是"通过"，执行轨迹里有失败记录 |
| 数据过期（时点 > 4 天） | ⚠️，原因写明"过期"及数据时点 |
| 标的不存在（3001） | ⚠️ "数据源中找不到标的" |
| 指定日期为非交易日（10-18 周日） | ⚠️ "非交易日或停牌" |
| 年报未披露（FY2026） | ⚠️ "没有 2026 年年报" |
| LLM 返回非法 JSON | 结论为"核查未完成"，规则合规扫描仍输出结果 |
| 不支持的指标（如市占率） | 降级为 unsupported，⚠️，不会被静默判为一致 |

### 极端 / 合规边界
| 用例 | 预期 |
|---|---|
| ③ 号稿件规则扫描 | 命中收益承诺（稳赚不赔、翻倍）、确定性预测（必涨、目标价）、买卖建议（逢低布局、上车）、操纵暗示（主力资金即将拉升） |
| ① 号合规稿件 | 规则层零命中（"不构成投资建议"不会被"建议"误伤） |
| LLM 编造了原文没有的违规片段 | 丢弃 |
| 只有"观点未标注"建议 | 不阻断，结论为"待合规签字" |
| 容差边界 | 精确 ±0.1pp、模糊 ±1pp；金额 1%；涨跌方向相反直接判不符 |
| 输入为空 / 超过 4000 字 / 非法 JSON | API 返回 400 和中文错误信息（`src/app/api/check/route.ts`） |

## 手工验收清单（线上 URL）

1. 点击"② 数据有错"→ 开始核查 → 应看到 3 条 ❌，红色高亮落在对应数字上
2. 对"大跌8.5%"点击"采纳"→ 修订稿变为"大跌12.03%"；点"撤销"后恢复原文
3. 点击"③ 合规风险"→ 至少 6 条合规标记，结论为"需修改后再发布"
4. 故障演练选"数据接口不可用"→ 所有数据项为 ⚠️，结论不是通过
5. 故障演练选"LLM 不可用"→ 结论为"核查未完成"，仍显示规则命中项
6. 下载核查报告 → Markdown 包含每条结论的来源、时点、口径和处理决策
