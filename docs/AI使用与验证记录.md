# AI 使用与验证记录

## 使用的 AI 工具

| 工具 | 用途 |
|---|---|
| Claude Code（Claude Opus 5.5） | 拆解题目、选择场景、制定 90 分钟计划；阅读扶摇 `llms-full.txt` 接口文档；编写全部代码、测试与文档；用真实接口跑冒烟测试 |
| DeepSeek `deepseek-flash`（产品运行时） | ① 从稿件中抽取结构化数值陈述；② 语义合规审查；③ 事实、推断、观点分句标注 |

## AI 在产品里的角色边界

- LLM **只负责理解和定位**：判断哪句话需要核查、核查什么指标、什么日期或窗口、比较方向是什么
- LLM **不产出任何数字**：所有数据都来自扶摇接口，所有计算（涨跌幅、同比、容差比对）都由确定性代码完成
- LLM 输出的引用片段必须是原文子串，否则丢弃，防止模型编造稿件里没有的陈述或违规点
- LLM 失败时降级：数据核查不做，结论标为"核查未完成"；合规关键词规则仍然执行

## 开发过程中发现并修正的问题

| # | 发现方式 | 问题 | 修正 |
|---|---|---|---|
| 1 | 首次调用 DeepSeek | 开启 JSON mode 后，模型仍返回了非法 JSON（`{"ok":No valid JSON...}`） | `llmJson` 严格解析，解析失败时显式报错并记入执行轨迹，不做"猜测修复" |
| 2 | 真实接口冒烟（① 号合规稿件） | LLM 把"2025年营业收入1688.38亿元，同比下降1.21%"这种历史财务事实误判为"确定性预测" | prompt 中明确"已发生的历史数据不属于预测，数字对错由另一模块负责" |
| 3 | 真实接口冒烟（② 号稿件） | LLM 对几乎每篇稿件都报"观点未标注"，如果都阻断发布，产品会不可用 | 新增 severity：观点未标注为 low，只作建议，不改变整体结论 |
| 4 | 设计评审 | "同比增长超过40%"（实际 42.28%）如果按等值比对会被误判为不符 | 抽取时增加 `comparator`（eq/gt/lt），比对时按单侧判断 |
| 5 | 单元测试 | 我手算的预期值写错了：宁德时代 10-21 跌幅 227.9/259.08−1 = −12.035%，应保留为 12.03%，我写成了 12.04% | 改正测试预期；代码本身是对的 |
| 6 | 单元测试 | 合规正则 `(主力\|机构)(即将\|准备)拉升` 漏掉了"主力**资金**即将拉升" | 允许中间有 0–4 个字 |
| 7 | 环境排查 | 本机路由器 DNS 间歇性解析不了 `fuyao.aicubes.cn`，导致全部核查变成"无法核实"。这也正好验证了降级逻辑：没有输出任何"一致" | 网络层错误重试 1 次；业务错误码不重试 |
| 8 | 脚手架检查 | create-next-app 覆盖了 `.gitignore`，并默认从 Google Fonts 加载字体（国内访问不稳） | 确认 `.env*` 仍被忽略并补上 `!.env.example`；删除 Google Fonts，改用系统中文字体 |
| 9 | 代码检查 | 区间涨跌幅的"数据过期"判断初版逻辑混乱，模拟过期时还会产生两条互相矛盾的分支 | 统一为一处 `lastTs` 判断 |
| 10 | 真实接口冒烟 | 稿件写"当日/同日"时，LLM 没有继承标题里的日期，退回用最新快照比对：② 号稿"同日茅台上涨0.5%"被拿去和 10-22 的数据比，而稿件说的是 10-21。过几天再跑，① 号稿也会误报 | prompt 规定"当日/同日"继承上文最近出现的日期；修复后两篇稿件都按正确交易日核查，茅台那条正确判为"方向相反" |
| 11 | 真实接口冒烟 | 加了 prompt 约束以后，LLM 仍然把"2025年营收…同比增长27%"标成"确定性预测" | 不再只靠 prompt：代码层要求"确定性预测"的片段必须含有指向未来的词（将、未来、后市、预计……），否则丢弃，并补了单测 |
| 12 | 环境排查 | 改了系统 DNS 以后，Node 的 getaddrinfo 仍然解析不了扶摇域名（curl、dig 都正常） | 增加仅本地使用的 `FUYAO_LOCAL_DNS=1` 开关，改用 c-ares 解析；生产环境不开启 |
| 13 | Cloudflare 本地预览 | Next 16.4 + OpenNext 在 workerd 中连首页都卡死（Worker hung） | 降级到 OpenNext 官方支持的 Next 15.5.28，功能代码无改动（只把 `LayoutProps` 换成显式类型） |
| 14 | Cloudflare 本地预览 | OpenNext 构建会把 `.env.local` 打包进 Worker，本地 DNS 开关被带进生产环境，Worker 去走 undici，报 `ALPNProtocols not implemented` | 开关改为只在 npm 脚本中设置；生产环境的 key 改用 `wrangler secret`，构建时不带 `.env.local` |
