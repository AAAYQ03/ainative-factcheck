## 2. 人与 AI 的分工

| 环节 | 候选人（我） | Claude Code |

## 3. AI 在产品里的角色边界（设计约束）

- LLM **只负责理解和定位**：判断哪句话需要核查、核查什么指标、什么日期或窗口、比较方向是什么
- LLM **不产出任何数字**：所有数据都来自扶摇接口，所有计算（涨跌幅、同比、容差比对）都由确定性代码完成
- LLM 输出的引用片段必须是原文子串，否则丢弃，防止模型编造稿件里没有的陈述或违规点
- LLM 失败时降级：不做数据核查，结论标为"核查未完成"；合规关键词规则照常执行
- 即使全部一致，结论也只是"待合规签字"，不是"可发布"：AI 不替人做最终决定

## 4. 开发过程中发现并修正的问题

### 4.1 LLM 输出的问题（产品质量风险）

| # | 发现方式 | 问题 | 修正 |
|---|---|---|---|
| 1 | 首次调用 DeepSeek | 开了 JSON mode，模型仍返回非法 JSON（`{"ok":No valid JSON...}`） | 严格解析，失败时显式报错并记入执行轨迹，不做"猜测修复" |
| 2 | 真实接口冒烟 | LLM 把"2025年营业收入1688.38亿元，同比下降1.21%"这种历史事实误判为"确定性预测" | 先在 prompt 里加约束，无效（见 #4） |
| 3 | 真实接口冒烟 | LLM 几乎对每篇稿件都报"观点未标注"，如果都阻断发布，产品会不可用 | 分级：观点未标注为 low，只作建议，不影响整体结论 |
| 4 | 真实接口冒烟 | 加了 prompt 约束以后，LLM 仍然把历史营收增速标成"确定性预测" | 不再只靠 prompt：代码层要求"确定性预测"的片段必须含有指向未来的词，否则丢弃，并补单测 |
| 5 | 真实接口冒烟 | 稿件写"当日/同日"时，LLM 没有继承标题里的日期，退回用最新行情比对。"同日茅台上涨0.5%"被拿去和 10-22 比，而稿件说的是 10-21；示例稿件过几天再跑也会误报 | prompt 规定继承上文最近的日期；修复后茅台那条正确判为"方向相反" |

### 4.2 核查逻辑的问题

| # | 发现方式 | 问题 | 修正 |
|---|---|---|---|
| 6 | 设计评审 | "同比增长超过40%"（实际 42.28%）如果按等值比对会被误判为不符 | 增加比较方向（eq/gt/lt），按单侧判断 |
| 7 | 单元测试 | 测试预期值手算错误：227.9/259.08−1 = −12.035%，应为 12.03%，写成了 12.04% | 改正预期；代码本身是对的 |
| 8 | 单元测试 | 合规规则漏掉"主力**资金**即将拉升" | 放宽正则 |
| 9 | 代码检查 | "数据过期"判断初版有两条互相矛盾的分支 | 合并为一处判断 |

### 4.3 工程与环境问题

| # | 发现方式 | 问题 | 修正 |
|---|---|---|---|
| 10 | 环境排查 | 本机 DNS 解析不了扶摇域名，所有核查都变成"无法核实"。这顺带验证了降级逻辑：没有输出任何"一致" | 网络错误重试 1 次；本地开发增加 `dev:localdns` 脚本 |
| 11 | 脚手架检查 | create-next-app 覆盖了 `.gitignore`，并默认从 Google Fonts 加载字体（国内不稳） | 确认 `.env*` 仍被忽略；改用系统中文字体 |
| 12 | Cloudflare 预览 | Next 16.4 + OpenNext 在 workerd 中连首页都卡死 | 降级到官方支持的 Next 15.5.28 |
| 13 | Cloudflare 预览 | OpenNext 构建会把 `.env.local` 打包进 Worker，本地 DNS 开关被带进生产环境 | 开关只在 npm 脚本里设置；线上 key 改用 `wrangler secret`，构建时不带 `.env.local` |
| 14 | 线上并发测试 | 6 个请求同时发起时，一次核查全部"无法核实"（推测为扶摇限流）；单独重跑恢复正常 | 没有误判为一致，符合设计；列入 README 已知边界，后续加队列和退避 |

## 5. 候选人复核记录

### 5.1 我做出的关键产品决策

1. **范围控制**：题目给 24 小时，我只投入 90 分钟，要求 AI 先出计划再动手，并据此接受了计划中的范围裁剪（不接 iFinD、不做季报、不做多用户后端）。
2. **场景选择**：采纳"投顾稿件核查"方案。我认可的理由是：赛题的统一规则（区分事实和推断、可溯源、失败不静默）在这个场景里本身就是产品功能，评审可以用构造的错误稿件直接验证产品是否有效。
3. **把可达性当作交付标准**：AI 默认推荐 Vercel，我判断评审在国内，`vercel.app` 打不开就等于没交，于是改为 Cloudflare 加自有域名。这是 AI 不了解的部署环境约束。
4. **数据安全由人把关**：AI 第一次就想直接执行命令，我叫停了，改成由我本人往空白 `.env.local` 里填 key，key 不进对话、不进仓库。公开仓库也由我亲自创建。
5. **区分两类 AI 使用**：我追问后厘清了"AI Coding 工具"和"产品运行时 LLM"是两件事。运行时模型按目标市场的可访问性和成本来选（DeepSeek），而不是选编码时用的模型。
